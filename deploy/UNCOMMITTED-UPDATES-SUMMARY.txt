HEADLINE
-------------------------------------------------------------------------------
A LIVE OUTBOUND PHONE CALL COMPLETED end-to-end through the new system, and the
working configuration is now built into the platform's sign-up flow. New
customers can be auto-provisioned with a working phone line.

WHAT THIS DOES (in plain terms)
-------------------------------------------------------------------------------
When a new company signs up, the platform automatically:
  - creates that company's phone-line account with our carrier (VoipSwitch),
  - gives it a phone number (caller ID) from our number pool,
  - configures the correct calling/routing settings,
  - adds starter calling credit (optional),
  - stores the credentials in our database,
  - and wires the phone server (FreeSWITCH) so the line can place calls.

VERIFIED WORKING (live, against the real carrier)
-------------------------------------------------------------------------------
  - Account creation, phone-line registration ("connecting to the carrier"),
    funding, suspend/reactivate - all working.
  - A real outbound call was placed and RANG the destination phone. Confirmed.

THE TWO PROBLEMS WE SOLVED ALONG THE WAY
-------------------------------------------------------------------------------
  1. The phone server was set to "local-only" (loopback). Binding it to the real
     network address fixed the line connecting to the carrier.
  2. Calls were being rejected ("payment required") because the test account was
     created under the wrong carrier reseller/price-plan. Creating it under
     NativeTalk's own master account, on a plan that has live call routes, plus
     the carrier's routing code (tech-prefix), made calls go through.
